red — архитектура редактора

# Общая идея

red — текстовый редактор в духе acme, реализованный на Lua поверх rein (`data/apps/red.lua`, `data/lib/red/*`). Основные идеи:

* окно — это буфер текста плюс «тег» (меню) сверху;
* команды не набираются в отдельной строке, а пишутся прямо в меню (или в буфере) и выполняются средней кнопкой мыши;
* рабочий стол состоит из вертикальных колонок; колонка — это список окон, которые можно разложить «стопкой» (stacked);
* сам редактор — обычное приложение rein: получает события `sys.input()`, рисует через `screen`/`gfx` и не знает про ОС.

Весь код — таблицы Lua с метатаблицами, без сторонних библиотек.

# Запуск и главный цикл

`data/boot.lua` (лаунчер rein) выбирает приложение и запускает его через `sys.exec`. Для red выполняется `apps/red.lua`:

1. `win:init(conf)` — инициализирует шрифт/экран (`scr`);
2. `win:make_keybinds(win_keys)` — пользовательские биндинги клавиш;
3. из `confdir` подгружаются `conf.lua`, `presets.lua`, `uri.lua`, `proc.lua`, `keys.lua` (см. `load_conf`);
4. создаётся `mainwin` с `mainmenu` и первой колонкой;
5. открываются файлы из argv; иначе загружается `red.dump`, а при его отсутствии открывается `./`.

Опции командной строки (`parse_options`): `-fs <размер шрифта>`, `-confdir <каталог>` (доп. конфигурация), `-nodump` (не загружать `red.dump`), `-fifo <путь>` (слушать именованный канал: каждая строка — файл для открытия, строка `quit` останавливает слушателя).

Главный цикл (`red.lua`, конец файла):

```lua
while not conf.stop do
  repeat r, v, a, b = sys.input() until r ~= 'wake'
  ...
  main:event(r, v, a, b)      -- обработка события
  main:show()                 -- отрисовка
  gfx.flip(main:process() or 10, true) -- корутины, пауза
end
```

`main:process()` возвращает частоту кадров (зависит от активных корутин); `gfx.flip` ждёт не дольше этого времени.

# Объекты и иерархия

```
mainwin                     -- корень (lib/red/frame.lua)
 ├── mainmenu               -- главное меню (Help GetAll ... New)
 └── frame                  -- колонка
      ├── framemenu         -- меню колонки (тег для tabbed/stacked)
      ├── win               -- окно (lib/red/win.lua)
      │    ├── buf          -- буфер (lib/red/buf.lua)
      │    └── menu_w       -- личное меню окна (только в stacked)
      └── win ...
```

* **`win`** (`lib/red/win.lua`) — базовый класс: буфер, шрифтовая сетка (`glyphs`), скроллер, курсор, отрисовка (`flush`/`show`), обработка событий, запуск корутин.
* **`buf`** (`lib/red/buf.lua`) — модель текста: массив UTF-8-символов, курсор `cur`, выделение `sel`, история `hist`/`redo_hist`, поиск, выделение слова/скобок.
* **`menu`** (`lib/red/menu.lua`) — наследник `win`: умеет исполнять слова (`menu:exec`), знает «своё» окно (`winmenu`).
* **`frame`** (`lib/red/frame.lua`) — колонка: меню + список окон, раскладка tabbed/stacked, перестановка и ресайз окон.
* **`mainwin`** — корневой frame; его `childs` — колонки, а раскладка по горизонтали (`hgeom`) делит ширину по долям `frac` (как stacked-окна по высоте).
* **`scr`** — экран и шрифт (`scr.spw`, `scr.sph`, `scr:glyph`).
* **`proc`** (`lib/red/proc.lua`) — таблица команд (`i+`, `dump`, `fmt`, `>`, `|`, ...); значения — функции, которые выполняются в корутинах.
* **`shell`** (`lib/red/shell.lua`) — запуск внешних программ и ввод-вывод (в т.ч. окна-оболочки `win`).
* **`syntax`** (`lib/red/syntax.lua`) — подсветка; схемы в `lib/red/syntax/*.lua`.
* **`conf`** (`lib/red/conf.lua`) — конфигурация; **`presets`** — настройки по маске имени файла; **`uri`** — обработка ссылок; **`keys`** — биндинги.

Объекты наследуются через метатаблицы: `win.__index = win`, `self.__index = self` в `win:new`/`frame:new`/`buf:new`. Ссылки вверх: `buf.win`, `win.frame`, `menu.frame`, `frame.frame`.

# Модель текста (buf)

Текст хранится не строкой, а **массивом символов**: `buf.text[i]` — одна руна UTF-8. Преобразование — `utf.chars`, `utf.len`, `utf.codepoint` (C-модуль `src/utf.c`). Поэтому все позиции (`cur`, `sel.s/e`) — индексы символов, а не байтов.

Ключевые поля: `cur`, `sel {s,e}`, `hist`, `redo_hist`, `is_changed`, `fname`, `written` (хеш для dirty-проверки). История — записи `{op='input'|'cut'|'start'|'end', pos, nr, data}`; `undo`/`redo` применяют их через общий `buf:apply_hist`.

Замена текста с сохранением курсора/выделения — `buf:set_keep` (используется при перестройке меню в `frame:update`). Курсор и выделение сдвигаются на дельту после первой различающейся позиции; если текст реально изменился, история отмены сбрасывается — внешняя перестройка управляемой строки делает старые шаги невалидными.

`buf:mark(pos)` запоминает минимальную изменённую позицию (`buf.changed_from`): его вызывают `history` (input/cut), `undo`/`redo`, `set`, `load`, `append`. Это нужно инкрементальной подсветке.

# Подсветка синтаксиса

Подсветка инкрементальная: `syntax` (`lib/red/syntax.lua`) читает `buf.text` как поток символов и хранит стек контекстов (строки, блочные комментарии, скобки). `win:colorize` вызывается из `win:show` и заполняет цвета `colorizer.cols`.

Чтобы правка в любом месте файла отражалась корректно и при этом не перекрашивать весь файл:

* колоризатор держит **чекпоинты** — снимки состояния лексера (`stack`, `pos`, `ctx`) каждые `colorize_checkpoint` символов (по умолчанию 1024, число ограничено `colorize_checkpoints`);
* при правке `win:colorize` берёт `buf.changed_from`, находит последний чекпоинт с `pos <= changed_from`, отбрасывает более поздние (невалидные) и лексит вперёд до конца видимой области, записывая новые чекпоинты; если валидного чекпоинта нет — полная пересборка;
* если изменений нет и видимая область уже покрашена (`colorizer.pos >= epos`), работа не делается; при прокрутке лексинг просто продолжается.

`syntax:state()` копирует стек, поэтому снимок не портится при лексинге. Стоимость правки пропорциональна расстоянию от неё до видимой области, а не размеру файла.

# Меню и исполнение команд

Меню — это тоже окно; его текст строится из имён файлов и слов-команд. Клик средней кнопкой по слову:

```
win:event -> win:mouseup -> win:get_active_text -> menu:exec
```

`menu:exec(t)`:

1. если у окна (`w:winmenu()`) есть `w.cmd[t]` — вызвать его;
2. иначе команда меню (`framemenu.cmd`, `mainmenu.cmd`);
3. иначе `win:exec(t)` — общий путь: `proc` → открытие файла по имени → `uri` (`@`, `!`, `|`, `>`).

Слова-«команды» могут быть вписаны в меню вручную — текст меню и есть командная строка. Левая кнопка ставит курсор, правая — ищет слово, средняя — исполняет.

Специальные окна задают свои команды через `w.cmd` (например, окно `+dump` — `{ Get = dump_export }`), а окна-оболочки — через `w.cmdline` (строка приглашения).

Текст меню — это «тег»: слева от `|` имена файлов и слова-команды, справа — командная строка. Состояние тега перестраивается в `frame:update`: в tabbed — `tab_menu_text` (`frame:win_menu_words` + хвост от `|`), в stacked — `stacked_menu_text` для меню колонки и `sync_win_menu` для меню каждого окна. Хвост после `|` берётся из текущего текста (правки командной строки сохраняются), а когда `|` исчезает — начинается заново. Общие куски вынесены в `frame.menu_tail` (часть после `|`), `frame.menu_filename` (имя файла из тега), `frame:rename_from_menu` (переименование окна по тегу) и `frame.win_words` (`[Put ]Close Get [cmdline]`). Меню, которому принадлежит командная строка окна (или меню), возвращает `frame:cmd_menu(w)`: своё `menu_w` в stacked (создаётся лениво через `new_win_menu`), меню колонки в tabbed. Перестройка идёт через `set_keep`, поэтому устаревшая история отмены меню сбрасывается.

# Колонки и режимы tabbed/stacked

`frame` — вертикальная колонка. В режиме **tabbed** сверху меню колонки с именами файлов, ниже — активное окно. В режиме **stacked** каждое окно получает собственное меню `menu_w`, и все окна видны.

Раскладка:

* `mainwin:hgeom` — делит ширину между колонками пропорционально долям `c.frac` (последняя забирает остаток), поэтому колонки ведут себя как stacked-окна по высоте;
* `frame:geom` — tabbed: меню + окна сверху вниз;
* `frame:geom_stacked` — список слотов `[menu_w][тело]`, высоты тел считает `frame:stacked_sizes` по долям `w.frac`;
* `frame:frac_norm` — общая нормализация долей `frac` (0 — допустимое значение): и для колонок в `mainwin`, и для окон внутри колонки. Новая колонка/окно получает долю `1/n`, остальные пересчитываются; при удалении оставшиеся доли занимают всё место.

Переключение — `frame:stacked_toggle` (средняя кнопка по скроллеру меню колонки). При сворачивании командная строка колонки и переименования из меню окон сохраняются; при разворачивании меню колонки получает хвост `| New ` (или сохранённую командную строку stacked).

В stacked командная строка окна живёт в `menu_w`, а в меню колонки остаются команды для всей колонки; при входе в stacked в нём гарантируется слово `New` (`frame.menu_has_word`), а `New` в меню окна вставляет новое окно сразу под ним (`framemenu.cmd:New`).

Мышь по меню окна в stacked:

* ЛКМ-протяжка за квадратик меню (скроллер, `x < scr.spw`) — одновременно ширина колонки (`mainwin:resize_col` по `dx`) и высота окна (`frame:resize_win(win, dy)`); остальная часть меню — только текст и команды;
* ПКМ-протяжка — перенос окна: `mainwin:move_win` находит колонку под курсором (`mainwin:frame_at`) и позицию вставки (`frame:win_at` — «под окном, в чьей области брошено»).

# События

`win:event(r, v, a, b)` — базовый диспетчер. Координаты `a,b` приходят в системе координат rein (как `self.x/self.y`), а методы окна получают локальные (за вычетом `self.x/self.y`).

| событие | действие |
|---|---|
| `mousedown`/`mouseup` | `win:mousedown`/`win:mouseup` |
| `mousemotion` | `win:motion` |
| `mousewheel` | `win:wheel` |
| `text` | `win:input` |
| `keydown` | `win:keydown_event` |

`keydown_event` — встроенные клавиши редактирования; всё остальное уходит в `win:handlekey`, где ищутся пользовательские биндинги `keybind` (`win:make_keybinds`).

События доставляются по иерархии `mainwin:event -> frame:event`. В stacked `frame:event_stacked` до рассылки по `menu_w` и окнам обрабатывает нажатие на меню окна (`frame.press` и `frame:press_event` в `red.lua`): ЛКМ за квадратик — ресайз колонки и окна, ПКМ — перенос; ниже порога `conf.drag_delta * SCALE` это считается кликом.

Важная особенность: `mousedown` получает только окно под курсором, а `mouseup`/`mousemotion` — все; поэтому обработчики сами проверяют координаты и состояние.

# Корутины

Долгие операции (запуск программ, чтение вывода, обработка текста) выполняются в корутинах, чтобы редактор оставался отзывчивым.

API окна:

```lua
function win:run(fn, ...)        -- создать корутину
  local c = { coroutine.create(fn), self, ... }
  table.insert(self.co, c)
  return c
end

function win:process()           -- резюмировать все корутины
  for _, v in ipairs(self.co) do
    if coroutine.status(v[1]) == 'suspended' then
      local r, e = coroutine.resume(table.unpack(v))
      if not r then return false, e end  -- ошибку покажет frame:err
      ...
    end
  end
  ...
end
```

`fn` получает первым аргументом само окно (`self`), затем все переданные параметры. `coroutine.yield()` возвращает управление главному циклу; `win:process` будет вызывать корутину снова (частота зависит от `conf.proc_hz`/`conf.idle_hz`), пока она не завершится. `win:killproc` и `w.kill` прерывают работу.

Команды `proc` — обычные функции, которые `win:exec` ставит в очередь корутин (`win:proc` → `win:run`). Пример собственной команды:

```lua
-- слово "tick" в меню запустит это; редактор не блокируется
function proc.tick(w)
  w = w:winmenu()          -- окно с данными (меню -> его окно)
  if not w then return end
  for i = 1, 10 do
    w:append(("tick %d\n"):format(i))
    coroutine.yield()      -- отдать управление, продолжить позже
  end
end
```

Функция-команда получает `w` — то окно/меню, на котором вызван `exec`; `w:winmenu()` возвращает связанное окно с данными (для меню колонки — активное окно, для `menu_w` — своё).

`shell.pipe` — пример сложной корутины: запускает внешний процесс в отдельном потоке (`thread.start`) и в цикле переносит его вывод в буфер, иногда уступая (`coroutine.yield`). Ошибки корутин обрабатываются в `frame:process` и выводятся в окно `+Errors` (`frame:err`).

Окно, у которого есть `menu_w`, процессит и его корутины: `win:process` в конце вызывает `self.menu_w:process()`.

# Команды, оболочка, вывод

* `proc` — слова-команды: `i+`, `i-`, `dump`, `fmt`, `par`, `grep`, `cat`, `>`, `|`, `@`, `!`, `win` и т.д.
* `>prog`, `|prog`, `<prog`, `@prog` — запуск внешних программ через `shell.pipe`; вывод идёт в окно `+Output` или в буфер.
* `win` — псевдо-acme окно-оболочка (`shell.win`) с командной строкой `cmdline`; esc закрывает ввод.
* Служебные окна: `+Errors`, `+Output`, `+dump`, `+Help`; в stacked новые служебные окна добавляются в конец столбца (`frame:open_err`).

# Рабочий каталог (cwd)

У каждого окна есть необязательное поле `w.cwd` — каталог, относительно которого разрешаются относительные пути. Это не глобальный каталог процесса: у разных окон `cwd` может быть своим.

Как устанавливается:

* при открытии файла — `frame:file`: `cwd` окна = `sys.realpath(sys.dirname(fn))`, для каталога — сам каталог; `win:getcwd()` (каталог файла, показанного в меню колонки) используется в `frame:update`, если у активного окна `cwd` ещё нет;
* при открытии каталога — `win:exec`, ветка `buf:isdir()`: `self.cwd = sys.realpath(ff)`, а буфер становится листингом каталога;
* в окне-оболочке (`shell.win`) — команда `cd` в `shell:execute`: `self.cwd = sys.realpath(cwd)` и перерисовка меню через `self.frame:update(true)`;
* у окон вывода — `menu:output`: новый `+Output`/`+dump` получает `cwd` того окна/меню, из которого его открыли (`self:getcwd()`); исключение — `+grep`, где `proc.grep` явно ставит `w.cwd = nil`;
* при восстановлении сессии — `load_dump`: `fr:win().cwd = b.cwd`; при сохранении (`mainmenu.cmd:Dump`) `cwd` каждого окна пишется в `red.dump`.

Где используется:

* `win:path(t, from)` — приводит относительный путь `t` к виду относительно `from` (по умолчанию `./`) с учётом `cwd`; на этом построены автодополнение (`win:completion`), переходы по ссылкам и `cd`/`ls` в оболочке; если относительный путь уходит вверх (`..`) и от этого длиннее канонического, возвращается абсолютный путь;
* `shell.pipe` передаёт `w.cwd` в поток, и команда выполняется как `cd <cwd> && <команда>`;
* тем самым команды, запущенные из окна, работают в каталоге этого окна, а не редактора в целом.

# Конфигурация и состояние

`conf` — глобальные настройки (шрифт, цвета, частота корутин, `syntax`, `nodump`...). `presets` — таблица правил «маска имени файла → настройки окна». `keys`, `proc`, `uri`, `conf`, `presets` можно расширять файлами из `confdir`.

Сессия сохраняется в `red.dump` (`dumper`): режим и доли колонок/окон (`stacked`, `frac`), командные строки (`stacked_cmdline`, `w.cmdline`), тексты и меню окон, порядок окон. Окна-оболочки дополнительно сохраняют shell-состояние (`output_pos`, историю команд, `scroll_mode`) и восстанавливаются вызовом `shell.win`. Позиции в файлах — в `red.hist` (`win:histfile_add`/`histfile_get`).

# Соглашения

* Текст — массив UTF-8-символов; длина цикла — `#buf.text`, символ — `buf.text[i]`.
* Координаты: события — в «экранной» системе rein, методы окон — локальные.
* Отрисовка: `flush` заполняет `glyphs`, `show` рисует текст и курсор; перерисовка кадра — `main:show()`.
* `scr.grab` — «идёт перетаскивание»: `frame:show` в это время не перерисовывает, чтобы не мешать ресайзу.
* Никаких блокирующих вызовов в обработчиках: длинные операции — только через `win:run` + `coroutine.yield`.
